# Version 1c: Keyboard and Gamepad Teleop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native execution, as approved for V1). Steps use checkbox syntax.

**Goal:** Drive the simulated robot by hand: a keyboard node and a gamepad node that publish `/cmd_vel`, `/body_pose_cmd`, `/gait_cmd` and call `/stand` and `/sit` (roadmap step 1.7).

**Architecture:** All key and stick handling is ROS-free (`bemu_teleop.mapping`), tested headless. Two thin nodes (`keyboard`, `gamepad`) move messages. `robot.launch.py` gains `teleop:=none|gamepad|keyboard`.

**Tech Stack:** Python, rclpy, `sensor_msgs/Joy` from the `joy` package, `termios` for the keyboard.

**Spec:** this plan is the design (roadmap row 1.7, `docs/05-software-stack.md` `bemu_teleop` and the `teleop` launch argument). My calls, recorded as rulings: a terminal has no key-release event, so keyboard control is *latched*: keys step the commanded speed and space stops; the keyboard node must run in its own terminal (`ros2 run bemu_teleop keyboard`), and `teleop:=keyboard` in the launch only prints that instruction. The gamepad is stateless: each `Joy` message becomes one command, scaled to the current gait's top speed. Releasing the sticks stops the robot (and the walker's 0.5 s timeout covers a lost controller).

## Global Constraints

- Speeds never exceed the current gait's top speed: forward and sideways `max_stride / (duty * cycle_time)` (tripod 0.12, ripple 0.06, wave 0.024 m/s), turn rate that speed divided by the farthest neutral foot radius.
- Body height command stays within ±10 mm of `stand_height` (the tested range); position z of `/body_pose_cmd` is the absolute hip height.
- Gamepad deadzone 0.1 on every axis; defaults assume an Xbox pad under Linux (axes: left X 0, left Y 1, right X 3; buttons: A 0 stand, B 1 sit, X 2 tripod, Y 3 ripple, RB 5 wave, LB 4 hold for slow mode at 30% speed); every index is a ROS parameter.
- Keyboard: `w`/`s` forward and back speed ±20% of top, `a`/`d` left and right, `q`/`e` turn left and right, space stop, `1`/`2`/`3` tripod/ripple/wave, `r`/`f` body up/down 5 mm, `h` stand, `j` sit, `x` quit.
- Ruff clean; headless tests run in the `python` CI job; `rclpy` tests use `importorskip`.

## Review Focus

1. A NaN or out-of-range axis value in `Joy` (or an axes list that is too short): ignored with a warning, never a crash or a full-speed command.
2. A gamepad disconnecting (no more `Joy` messages): the robot stops via the walker's timeout; a `Joy` message with all sticks centred publishes an explicit zero.
3. Pressing keys faster than the loop, or an unknown key: no effect, no crash; repeated `w` stops at the top speed.
4. Changing gait while latched at a speed above the new gait's top speed: the speed is clamped down to the new top speed.

### Task 1: The ROS-free mapping

**Files:** Create `ros2_ws/src/bemu_teleop/{package.xml,setup.py,setup.cfg,resource/bemu_teleop,bemu_teleop/__init__.py,bemu_teleop/mapping.py}`; Test `ros2_ws/src/bemu_teleop/test/test_mapping.py`; modify `pyproject.toml` (first-party and pythonpath).

**Interfaces:**
```python
def top_speeds(params: RobotParams, gait_params: GaitParams, gait: str) -> tuple[float, float, float]  # vx, vy, omega maxima
@dataclass(frozen=True)
class Action:  # what a key or button asks for besides motion
    kind: str  # "stand" | "sit" | "gait" | "height" | "quit"
    gait: str = ""        # for "gait"
    height: float = 0.0   # for "height": the new absolute hip height, metres
class KeyboardMapper:
    def __init__(self, params, gait_params, gait="tripod")
    velocity: tuple[float, float, float]   # latched
    gait: str; height: float
    def press(self, key: str) -> Action | None   # updates state; returns an Action for non-motion keys
@dataclass(frozen=True)
class JoyConfig:  # indices and tuning, all ROS parameters in the node
    axis_x: int = 0; axis_y: int = 1; axis_turn: int = 3
    button_stand: int = 0; button_sit: int = 1; button_tripod: int = 2; button_ripple: int = 3; button_wave: int = 5
    button_slow: int = 4; deadzone: float = 0.1; slow_scale: float = 0.3
def joy_command(axes, buttons, config, top: tuple[float, float, float]) -> tuple[float, float, float]  # raises ValueError for NaN/short axes
def joy_actions(buttons, previous_buttons, config) -> list[Action]  # edge-triggered: only newly pressed buttons
```
Stick conventions: pushing the left stick forward (axis Y positive on Linux `joy`) is forward, axis X positive is left, right-stick X positive is turn left; values are deadzoned and rescaled so just outside the deadzone is near zero and full deflection is exactly the top speed.

### Task 2: Nodes, launch argument, entry points

**Files:** Create `bemu_teleop/keyboard.py`, `bemu_teleop/gamepad.py`; modify `setup.py` (entry points `keyboard = bemu_teleop.keyboard:main`, `gamepad = bemu_teleop.gamepad:main`), `package.xml` (depends `rclpy`, `geometry_msgs`, `sensor_msgs`, `std_srvs`, `bemu_msgs`, `bemu_params`, `bemu_gait`, `bemu_kinematics`; `exec_depend` `joy`), `bemu_bringup/launch/robot.launch.py` (`teleop` argument), `bemu_bringup/package.xml` (`exec_depend` `bemu_teleop`); Test `test_nodes.py` (rclpy, `importorskip`, `ROS_DOMAIN_ID=80`) and extend `test_robot_launch_description.py`.

**Interfaces:** `keyboard` node: reads raw stdin (`termios`/`tty`, restored on exit, refuses with one line `keyboard: stdin is not a terminal` and exit 1 when it is not a tty), publishes `TwistStamped` on `/cmd_vel` at 10 Hz from the latched velocity, `PoseStamped` on `/body_pose_cmd` and `GaitCommand` on `/gait_cmd` on change, calls `/stand` and `/sit`; prints the key help at start. `gamepad` node: subscribes `/joy`, publishes the same topics; parameters for every `JoyConfig` field plus `params_file`; follows `/gait_state` so stick scaling uses the walker's current gait; a bad `Joy` logs a throttled warning and publishes nothing new. Launch: `teleop:=gamepad` starts `joy_node` (package `joy`, executable `joy_node`) and `gamepad`; `teleop:=keyboard` logs `Run: ros2 run bemu_teleop keyboard (in its own terminal)`; any other value but `none` raises `RuntimeError`.
